# Review candidate and historical proof boundary

The review changes gameplay, saves, aiming, shops, text and presentation. The
soundtrack-only contract still describes the exact released main tree
`cc5e88edcd27722d4e48c449fcc8d7d94f87f733`; it cannot authenticate this broader
candidate. Its contract, inverse, prior contracts and historical tests remain
unchanged.

`tests/verify_review_successor.py` authenticates the complete current production
file set (`src`, `assets`, linker, Makefile and Apache license), immutable prior
proof inputs and a finite inverse. The inverse reconstructs every tracked file
of prior main and recomputes its original Git tree identity. Original soundtrack,
font, endroll, UI and renderer proofs run on that exact historical tree only.
Music transport, catalog, PCM inputs and licenses must retain their exact main
hashes. Unexpected, deleted or edited current inputs, proof edits, contract edits
and inverse tampering fail closed, with a clean positive before negative controls.
Python `__pycache__` directories generated by host tooling are excluded from the
authored file inventory.

The inverse is never a ROM build input. Current engine, save, shop, companion,
geometry, UI pixel and native tests still use the actual current candidate.
Historical pixels do not establish current pixels or current gameplay.

After the complete runtime commit is reviewed, author its boundary from committed
Git objects. The helper writes only the new contract, inverse and verifier hash:

```sh
python3 tests/author_review_successor.py --repo . \
  --candidate-ref <reviewed-runtime-sha> --output-root .
python3 tests/test_review_successor.py
python3 tests/verify_review_successor.py
python3 tests/verify_review_successor.py --renderer-negatives
python3 tests/verify_review_successor.py --historical-ui
python3 tests/verify_review_successor.py --historical-ui --parent
python3 tests/verify_review_successor.py --current-geometry
```

The helper is deterministic and cannot repin prior artifacts or music/license
changes. CI executes verification, never authoring. A later runtime or authored
asset edit requires a newly reviewed candidate and a new current boundary pin.
Test/report-only commits do not change the authenticated production bytes.
